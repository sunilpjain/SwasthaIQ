# DIG-23 spike: Bedrock models and Textract in Mumbai (ap-south-1)

Checked on 17 Nov 2026 (Textract) and 27 Nov 2026 (Claude, after the AWS account moved to Pay by Invoice) with `api/scripts/spike-bedrock/run.ts`. All inputs are synthetic: the lab report is generated by `make-sample.py`, and the transcripts come from the DIG-25 spike.

## Decision

- **LLM:** Claude Opus 5 via the Bedrock inference profile **`in.anthropic.claude-opus-5`**, which routes only within India (ap-south-1 and ap-south-2), so no patient data leaves India. Chosen on 17 Nov 2026 over the newer Opus 5.5, because Opus 5.5 is available only through a `global.*` profile that may run in any region. Still true on 27 Nov 2026: ap-south-1 lists `in.*` profiles only for Opus 5, Sonnet 5 and Haiku 4.5.
- **Client:** `AnthropicBedrock` from `@anthropic-ai/bedrock-sdk`, which uses the InvokeModel API. The newer Bedrock Messages endpoint ("Mantle") returns 404 for every Claude model in ap-south-1.
- **OCR:** Textract `AnalyzeDocument` with `FeatureTypes: ['TABLES']` in ap-south-1.
- **Cross-region inference:** don't use it. It is allowed only if a needed model has no `in.*` profile, only with synthetic data, and only with the decision recorded in CLAUDE.md.

This decision is recorded in `CLAUDE.md`.

## Models available in ap-south-1

Every current Claude model in Mumbai needs an inference profile. Calling a model ID directly (on-demand) returns HTTP 400.

Other models with India-only profiles: `in.openai.gpt-5.6-*` and `in.moonshotai.kimi-k3*`. Amazon Nova is available through `apac.*` and `global.*` profiles. Non-Claude models are out of scope (see CLAUDE.md).

**Model access:** Bedrock reports `AUTHORIZED` for the account. Using a model needs an AWS Marketplace agreement for it, which needs a payment method Marketplace accepts. An Indian debit card was refused (`INVALID_PAYMENT_INSTRUMENT`); after the account moved to **Pay by Invoice**, resubmitting the agreement (`aws bedrock create-foundation-model-agreement`) went from `PENDING` to `AVAILABLE` within minutes. The first calls still returned the old 403 for about 5 more minutes, as AWS's error message warns. A new model needs its own agreement the same way.

## Results

### Textract AnalyzeDocument (TABLES): ✅

The input is `sample-lab-report.png`, a synthetic LFT report rendered as a phone photo: tilted 2.2°, with uneven light and noise. The tilt shifts the right-hand columns by about one row across the page.

| Measure               | Result                                                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Values read correctly | **10/10**, every row aligned correctly despite the tilt                                                                                          |
| Columns               | Test, Result, Flag, Units and Ref. range, all detected                                                                                           |
| Flags (H)             | 4/4                                                                                                                                              |
| Reference ranges      | All digits correct. Textract sometimes drops the dash (`7 56` for `7 - 56`); normalise in the parser.                                            |
| Latency               | 2.2–2.5 s for one page                                                                                                                           |
| Gotcha                | The patient header block comes back as a separate small table. Pick the results table by size or by its header row, not the first `TABLE` block. |

### Claude structuring and image reading: ✅

Run on 27 Nov 2026 through `in.anthropic.claude-opus-5` from ap-south-1, with structured outputs (`output_config.format`, JSON schema) and effort `medium`. Every call ended with `stop_reason: end_turn`.

| Test                                        | Result                                                          | Latency | Tokens in / out | Cost   |
| ------------------------------------------- | --------------------------------------------------------------- | ------- | --------------- | ------ |
| Structuring, English gastro transcript      | Rx **2/2** (drug and dose), investigations **1/1**, no extra Rx | 4.2 s   | 854 / 192       | $0.009 |
| Structuring, Hindi-English mixed transcript | Rx **1/1**, investigations **1/1**, no extra Rx                 | 2.0 s   | 836 / 157       | $0.008 |
| Lab-report photo to JSON rows               | Values **10/10**, reference ranges **3/3**, nothing wrong       | 5.6 s   | 3,166 / 512     | $0.029 |

What stood out:

- **Mixed language works.** The Hindi-English transcript came back as clean English fields ("Fever for three days", "Ursodeoxycholic acid 300 mg twice daily"), with ultrasound and LFT findings put under investigations.
- **Claude read the reference ranges better than Textract** on the tilted photo: 3/3 against Textract's 1/3, where Textract dropped the dash (`7 56` for `7 - 56`). Values were 10/10 for both. For DIG-63 this supports Textract for the table layout plus the LLM to check ranges, as the OCR story already plans.
- **No invented content:** neither transcript produced a medicine that wasn't dictated (`extraRx: 0`), and fields with nothing said came back as `null`.
- Costs use Anthropic's list price for Opus 5 ($5 / $25 per million tokens); Bedrock bills separately (see Cost notes).

## Cost notes

Approximate figures; check the Bedrock pricing page for India profile rates.

- Textract tables cost about $0.015 per page, so about ₹1.3 per lab report.
- Claude Opus 5 lists at $5 / $25 per million input/output tokens (Anthropic list price; Bedrock pricing is set separately). Measured on 27 Nov: a structuring call is about 850 tokens in and 150–200 out, about $0.009 (under ₹1); reading one lab-report photo is about 3,200 in and 500 out, about $0.03 (about ₹2.5).
- Every call must write `usage_events` (tokens, pages).
